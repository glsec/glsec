# GL021 — Secret variable printed to job log

**Severity:** `warn`  
**OWASP:** [CICD-SEC-6 – Insufficient Credential Hygiene](https://owasp.org/www-project-top-10-ci-cd-security-risks/CICD-SEC-06-Insufficient-Credential-Hygiene)

## What glsec checks

glsec flags script lines that pass a CI variable with a secret-indicating name directly to a print command (`echo`, `printf`, `print`, or PowerShell's `Write-Host`, `Write-Output`, `Write-Information`, and `write` alias). GitLab's log masking may fail to redact the value if it is shorter than the masking threshold, contains special characters, or appears in certain output contexts — causing it to appear in plain text in the job log.

PowerShell references `$env:NAME` and `${env:NAME}` are supported, with the `env:` prefix in any case. The PowerShell command names above and the secret-name checks for environment references are case insensitive; POSIX variable-name checks keep their existing case sensitivity. Single-quoted PowerShell strings do not expand variables and are not reported, just like single-quoted POSIX strings. See Microsoft's [environment-variable syntax](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_environment_variables) and [quoting rules](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_quoting_rules).

Variables are considered secret if their name contains one of `_TOKEN`, `_SECRET`, `_PASSWORD`, `_PASSWD`, `_PASS`, `_PWD`, `_KEY`, `_CREDENTIAL`, `_CERT` after at least one other character, so `DEPLOY_TOKEN` and `SECRET_KEY_BASE` both count. A name that ends in a segment naming something other than the secret value is not a secret: `_ID`, `_URL`, `_URI`, `_PATH`, `_FILE`, `_NAME`, `_HOST`, `_USER`, `_USERNAME`, `_TYPE`, `_LENGTH`, `_EXPIRES_AT`, or `DIR` (`GPG_KEY_ID`, `DOCKER_PASSWORD_FILE`, `DOCKER_TLS_CERTDIR`).

A line continued with `\` is read together with its continuation, so a redirect or pipe on the next physical line counts.

## Trigger example

```yaml
debug:
  script:
    - echo $CI_JOB_TOKEN
    - echo $DEPLOY_PASSWORD
    - printf "%s\n" "$API_SECRET"
```

PowerShell on a Windows runner:

```yaml
debug:
  tags: [windows]
  script:
    - Write-Host "token is $env:DEPLOY_TOKEN"
    - echo ${env:DEPLOY_PASSWORD}
    - Write-Information $env:API_SECRET -InformationAction Continue
```

## Safe alternatives

**Check presence without printing the value:**

```yaml
debug:
  script:
    - '[ -n "$CI_JOB_TOKEN" ] && echo "token is set" || echo "token is missing"'
```

**Print masked confirmation:**

```yaml
debug:
  script:
    - echo "Token length${CI_JOB_TOKEN:+ (set)}"
```

**Pipe the secret into a command's stdin** (not flagged) — the value goes to the command, not the log:

```yaml
build:
  before_script:
    - echo "$CI_REGISTRY_PASSWORD" | docker login --username "$CI_REGISTRY_USER" --password-stdin "$CI_REGISTRY"
  script:
    - ./build.sh
```

## Known limitations

- Lines where `: ` (colon space) appears inside the script command may be parsed by YAML as a mapping and will not be scanned. Use single-quoted scalars in `.gitlab-ci.yml` to avoid YAML parsing ambiguity: `- 'echo $MY_TOKEN'`.
- Detection is based on variable name patterns, not on whether GitLab has actually masked the variable. A variable named `MY_DATA` would not be flagged even if it contains a secret.
- PowerShell output analysis is conservative: preference variables and information-stream merging are not fully modeled. `Write-Information` is checked even though its default preference is `SilentlyContinue`. `Write-Host` and `Write-Information` use the information stream, so an ordinary pipe, success-output redirect, or command substitution does not suppress the finding; direct `6>` / `6>>` and `*>` / `*>>` redirects do. See [PowerShell output streams](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_output_streams).

## False positives

Names whose last segment names something other than the secret (`_ID`, `_URL`, `_PATH`, `_FILE`, `_NAME`, `_HOST`, `_USER`, `_VERSION`, `_ENDPOINT`, `_DOMAIN`, `_PORT`, `_REGION`, `_MODE`, `_ENABLED`, …) are not reported, and neither is `$CI_RUNNER_SHORT_TOKEN`, which GitLab documents as an identifier.

If a variable name matches the pattern but its value is intentionally public (e.g. `ENVIRONMENT_KEY` used as a config key name, not a credential), suppress with:

```yaml
script:
  - echo $ENVIRONMENT_KEY  # glsec:ignore GL021 -- not a secret, public config key name
```
