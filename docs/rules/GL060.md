# GL060 — `docker run` mounting sensitive host paths

**Severity:** `error` for `/`, `/etc`, `/root`, `/proc`, `/sys`; `warn` for `/var/run`, `/run`, `/dev`, `/boot`  
**OWASP:** [CICD-SEC-7 – Insecure System Configuration](https://owasp.org/www-project-top-10-ci-cd-security-risks/CICD-SEC-07-Insecure-System-Configuration)  
**CWE:** [CWE-552 – Files or Directories Accessible to External Parties](https://cwe.mitre.org/data/definitions/552.html)

## Risk

Mounting sensitive host filesystem paths into a container via a container run command breaks container isolation. A compromised job or malicious dependency can read or write host files outside the container boundary.

Particularly dangerous source paths:

- `/` — full root filesystem access
- `/etc` — read/write system config (`/etc/passwd`, `/etc/shadow`, `/etc/sudoers`)
- `/root` — root home directory including SSH keys
- `/proc` — host process information and kernel interfaces
- `/sys` — kernel and hardware control interfaces
- `/var/run` and `/run` — runtime sockets and service state; on current distributions `/var/run` is a symlink to `/run`, so both spellings are the same directory (a `DOCKER_HOST` reference to a socket, rather than a mount, is covered by [GL055](GL055.md))

## Trigger example

```yaml
test:
  script:
    - docker run -v /:/host -it myimage chroot /host
```

Both `-v` and `--volume` are detected, as is the `--mount` form with `type=bind` and a `source=` (or `src=`) host path; a `--mount` with `type=volume` and a named volume is not flagged. `docker`, `podman`, and `nerdctl` run and create commands are covered, including `docker container run`. **The source side of the bind mount is what matters** — `-v /etc:/anything` is flagged regardless of the destination inside the container. Subpaths count too (`-v /root/.ssh:/keys`).

```yaml
test:
  script:
    - docker run --mount type=bind,source=/etc,target=/x myimage
```

## Safe alternative

Mount only the specific project directory or a named Docker volume:

```yaml
test:
  script:
    - docker run -v $CI_PROJECT_DIR:/app myimage ./test.sh
```

## Notes

- `error` for `/`, `/etc`, `/root`, `/proc`, `/sys`; `warn` for `/var/run`, `/run`, `/dev`, `/boot`.
- Named volumes (`-v cache:/cache` and `--mount type=volume,source=name`), relative paths, and non-sensitive absolute paths (`/tmp/build`) are not flagged.
- Read-only mounts (`:ro`, `readonly`) of `/etc/passwd`, `/etc/group`, `/etc/localtime` and `/etc/timezone`, used to map the runner's user or time zone, are not flagged. Other read-only mounts are, with a message saying the job can read the host files.
- Ownership: this rule reports bind mounts in scripts, including socket mounts, once. A `DOCKER_HOST` reference to a socket is reported by [GL055](GL055.md), not here, so one socket reference yields one finding, not two.
- Related: [GL055](GL055.md) (Docker socket mount), [GL056](GL056.md) (`--privileged`).
- Script-line rule; assumes POSIX shell (see the README *Shell assumptions* note).
- Suppress per-file with `.glsec-ignore` or inline `# glsec:ignore GL060`.
